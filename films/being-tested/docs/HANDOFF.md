# Handoff: Being Tested (read this first in a new session)

This is a music video for the user's own Suno track "Being Tested" (3:30.8, 130→138 bpm drift), built
with the motion-reel skill. Branch: `claude/claude-music-video-0gps4j`. Work from `films/` and
call the skill folder `<skill>` (the motion-reel plugin's `skills/motion-reel`; find it with
`ls -d ~/.claude/plugins/**/skills/motion-reel`).

- **Model search (session 2):** VRoid's AvatarSample_A-C are under more restrictive terms (left out of the CC0

- **Remaining (not blocking):** the spiral stair (b203-212) is the darkest 4 s by design; VRoid's bang cards

## GPU renders on RunPod

- The key comes from the env var `RUNPOD_API_KEY` only; never print it or write it anywhere.
- `tools/runpod.py create --job probe|contact|render|custom [--args "..."] [--gpu "A,B"] [--vcpu N]` creates a
  pod on `mcr.microsoft.com/playwright:v1.56.1-noble` with `NVIDIA_DRIVER_CAPABILITIES=all`. Its start command
  clones this branch at the pushed HEAD, installs ffmpeg and the Vulkan loader, runs the job's fixed commands
  and serves `/work/out` read-only on port 8000 through RunPod's HTTPS proxy. The pod takes no commands after
  creation. **Push before creating a pod**: it renders the pushed commit. Picture renders need no audio, so the
  song never leaves this machine.
- `runpod.py status`, `get <file> <dest>` and `kill` (always kill: billing runs until then). Set
  `RUNPOD_STATE` to a scratch path; it records the current pod id. Cloudflare refuses urllib's default
  User-Agent (error 1010), so the script sends its own.
- `render.mjs --gpu` on Linux uses `--use-angle=vulkan --enable-features=Vulkan --disable-vulkan-surface`
  (`tools/gpuprobe.mjs` compares flag sets). A film frame takes ~40 ms on the GPU, but each screenshot takes
  ~500 ms and pages in one browser capture one at a time, so pass `--browsers N` (new in render.mjs) to spread
  the workers over N Chromium instances. Contact passes ran at 2-3 fps with one browser.
- "No instances available" is common for a single GPU type: pass a list of GPUs, lower `--vcpu`, or use
  `--cloud SECURE`.

## Not in the repo (it is public): restore first

- **The song.** It is the user's work, so never commit it. The `.gitignore` already covers
  `*/audio/*.mp3`, `*.wav` and `stems/`. Ask the user to re-upload the mp3 if it isn't in the session's
  uploads, then:
  ```
  cp <upload>.mp3 being-tested/audio/song.mp3
  uv run <skill>/scripts/beats.py being-tested --track being-tested/audio/song.mp3 --full   # writes audio/music.wav (48 kHz, 24-bit)
  git checkout -- being-tested/beats.json being-tested/film.json   # keep the committed tempo map + film settings
  ```
  The committed `beats.json` comes from `tools/tempomap.py`. It holds one measured time per beat, and
  `lib/motion.js` U/TS interpolate through it. A straight grid drifts up to 200 ms.
- **The vocal stem** is only needed to redo lyric timing; `lyrics.json` and `lipsync.json` are
  committed. It came from the npm `demucs` package (ONNX htdemucs). Install it with `--ignore-scripts`,
  because onnxruntime-node's postinstall pulls from nuget. Its weights are for personal/research use, so
  the stem was used for analysis only. Alignment used PocketSphinx via `tools/sphinx_align.py` and
  `tools/refine.py`. Repeats are copied on the beat map: chorus 2 is chorus 1 + 136 beats, and final
  chorus lines 1, 5 and 6 are chorus 1 + 297 beats.
- **`out/`** (contact sheets, stills) is regenerated by `render.mjs`.
- **Setup:** `cd films && npm ci`. Playwright's Chromium is preinstalled at
  `/opt/pw-browsers`; do not run `playwright install`.

## Shino: the facts

- **Format.** She is **VRM 0.x** (`extensions.VRM`) with 54 humanoid bones. Her eye height is about
  1.481 m in VRM space.
- **Blend shapes.** She has a, i, u, e, o, blink, blink_l, blink_r, angry, fun, joy and sorrow, plus two
  custom ones, "Surprised" and "Extra". three-vrm maps the presets to aa, ih, ou, ee, oh, happy (joy),
  relaxed (fun) and sad (sorrow). "Surprised" is custom, so check its name with
  `expressionManager.getExpression`. "Extra" shows the `>` `<` squint eyes (tex 14), which are good
  for a laugh beat.
- **Meshes.**
  - `Face.baked` uses materials 0–8.
  - `Body.baked` uses materials 9–13.
  - `Hair001.baked` uses material 15 on 46 strand primitives and material 16 on 2 primitives, which
    are **the blue X hairclip**. Recolour the clip to clay, or hide it and keep the spark hairpin.
- **MToon parameters per material.** Tex is the `_MainTex` texture index; _Color and _ShadeColor are
  linear values.

  | # | material | tex | _Color | _ShadeColor | notes |

  | 1 | EyeWhite | 4 | 1 | 1 | |

  | 3 | FaceEyelash | 7 | .44 .16 .16 | .41 .20 .12 | queue 4500 |

  view-space normal uv and add them.

## The singer as built (`sets/singer.js`)

- `loadSinger(look, base, file = 'assets/vrm/shino.vrm')`. VRM 0: `rotateVRM0`, then FK eulers authored for
  VRM 1 are mirrored `[x, y, z] -> [-x, y, -z]` in one place (`eul()` in `applyPose`), the hips sway x too.
- The model is scaled so her eye bone sits at `FILM_EYE_Y` = 1.449 (the old model's): every hard-coded camera
  kept its framing. IK targets in POSES are scaled by `headY / 1.39` (~1 after the scale).
- IK: `armRest` is measured in `vrm.scene`'s local frame (where normalized bones rest at identity) and targets
  go through `root` (character space). Pole and lower-arm axes are unchanged for VRM 0.
- Materials stay three-vrm `MToonMaterial`. `hookMToon` chains onto MToon's own `onBeforeCompile` and splices
  rim/scan/tint/lift/glow/dissolve/explode before the last `gl_FragColor`. **Meshes share materials** (all
  46 hair strands use one): hook each material once (`userData.styled`), or the program fails with
  "redefinition" and the hair vanishes.
- Cel ramps per class `[toony, shift, matcap]`: face [0.6, 0.18, 0.25], skin [0.8, 0.02, 0.3],
  hair [0.86, 0.04, 0.65], cloth [0.86, -0.02, 0.35]. VRoid ships 0.05-0.35, which reads as plastic.
- Recolours: hair strands get a root-to-tip gradient along v times the strand detail (ratio to the row
  mean); the spec map (emissiveMap) is the peach angel ring. Tops: shirt/piping/vest/rib by uv region
  (`topsTex`, V-neck polygon `V_IN`/`V_OUT`), slate line in the ribs, spark crest at uv (0.615, 0.6) = her left
  chest. Body: the base's white underwear becomes slate shorts. The X clip (`HAIR_02`) is hidden; the spark pin
  sits at its bounding-box centre facing out from the head.
- Expressions map through `EXPR` (VRM 0 customs keep their names: `Surprised`, `Extra` = the > < squint, usable
  as `mood.extra`). `singer.eyeX/eyeZ` are exported for eye macros.
- Lab: `lab/sheet.html?file=...&dbg=noOutline,noSprings,nan`, panels `lab/panels/shino1.json` and
  `twin1.json` (the model sheet), `lab/inspect.html?m=shino.vrm` lists meshes and MToon parameters.

## Traps already hit (don't repeat)

- `G.renderSet` calls the set's `update()` itself. Pass camera and pose options to `renderSet`; a
  separate `update()` call gets overwritten.
- Every set must set `singer.root.visible = true` and `setGravity(±1)` each frame. Frames render out of
  order, so leaked state causes black frames. Claude uses -1; the twin under the floor uses +1.
- Spring hair replays from rest over WARM = 18 steps on every call, which keeps frames pure. Keep that
  with the new model's spring bones (VRM0 `secondaryAnimation`, which three-vrm handles).
- Colours fed to custom shaders are linear. Night walls came out grey until the colour went through
  `pow(c, 2.2)`. The points portrait colours were pre-linearised by mistake once.
- `uDissolve` must default to 100; at -10 the whole body vanished.
- The lab pages override `fetch` to prefix `../`. Skip `blob:` and `data:` URLs, or GLTFLoader breaks.
- The GL layer renders at 0.75 scale (1440×810) and is upscaled, with the 2-D glow, grain and vignette in
  `post.js`.
- Check any non-Latin glyph in both fonts before using it. Check marks are drawn, not typed.
