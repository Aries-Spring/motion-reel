# 3-D in a film (three.js)

Use 3-D when a shot needs real depth: a camera move through a space, a lit object, an instanced
crowd, a shader effect. Keep 2-D for type, characters and graphic devices. The film stays one 2-D
canvas: each 3-D set renders to an offscreen WebGL canvas and is drawn into the frame like an image,
so 2-D and 3-D layers stack in `draw()` in any order (background 2-D, a 3-D set, a 2-D character, type).

## Setup

- `node <skill>/scripts/scaffold.mjs <film> --3d` copies `lib/gl.js` and writes an import map into
  `index.html` that resolves `three` (and the opentype.js that TTFLoader wants) from the project's
  `node_modules`; nothing loads from a CDN at render time. Then `npm i three opentype.js`.
- Build every set once in `init()`: `await G.initGL({ font: 'fonts/display.ttf' }); S.room = roomSet();`
  `initGL` sets up the renderer, a RoomEnvironment env map (for physical materials), the bloom chain,
  and 3-D type in the film's own display face (`text3D`, `glyphs3D`).
- Render on the GPU. `render.mjs` launches Chromium on ANGLE Metal on macOS by default and prints the
  WebGL renderer; "SwiftShader" means software, about 80x slower (a 4,000-mesh scene: 239 ms vs 3 ms).
  Measured on a 2.5 min film with ~20 sets: 2-4 fps at 1080p60 with 12-sample motion blur, about 47 min.

## The set pattern

```js
export function mySet() {
  const scene = new THREE.Scene(), cam = G.camera(40);
  G.keyLights(scene);
  // ... build meshes once ...
  return { scene, camera: cam, bloom: 0.3, bloomThreshold: 0.85,
    update(t, u, o = {}) { /* set EVERY animated property from t, u and o */ } };
}
// in draw():  G.renderSet(ctx, S.room, t, u, { cam: [x, y, z], walls: k });
```

- **update() is a pure function of (t, u, opts).** Set every transform, uniform and visibility each
  call; never `+=`, never read the previous frame. The renderer seeks frames out of order across
  parallel pages, and motion blur calls update() 8-16 times per frame at sub-frame times.
- **Simulations run at build time.** A pile of 4,800 falling paperclips was a deterministic stacking
  pass over a heightmap in the set's constructor (spawn time, landing height, tumble per clip); update()
  only evaluates each clip's fall curve at t. The same for gradient-descent paths, particle targets,
  shatter shards (precomputed pieces, velocities, spins).
- **Shaders take time as a uniform.** Vertex displacement (a noise blob), a raymarched black hole, a
  particle morph between two poses: all uniforms set in update(), no `clock`.
- **Instancing** for anything repeated (cards, chips, seats, racks, shards): one InstancedMesh, matrices
  written in update(). Hide an instance with a zero-scale matrix.
- **One shared renderer.** Bloom is per set (`bloom`, `bloomThreshold`, `bloomRadius`); a set may change
  them in update() per mode. Sets without bloom render with a transparent clear, so 2-D shows through.

## 2-D inside 3-D

- Draw a 2-D layer (a character, a screen, a sign) into `G.canvasTexture(w, h)` with `tex.draw(fn)`
  each frame and put it on a plane (`MeshBasicMaterial({ map, transparent: true, alphaTest: 0.02 })`).
- **A flat card seen while the camera orbits reads as a cardboard cut-out.** Billboard it
  (`G.billboard(mesh, cam)`) and turn the drawing by the angle the camera sees it from
  (`G.viewYaw(camPos, objPos)`, clamped to the rig's range) so she turns with the view. With a
  2.5-D rig (references/examples/vector_rig.js) this reads as a figure standing in the room.
- Put real 3-D props in front of the card (a desk, a pile, a stage floor) so the parallax sells it.

## Gotchas (each cost a render)

- **Colour space.** Canvas pixels are sRGB. Colours sampled from a canvas into a ShaderMaterial
  attribute or uniform must be converted to linear (`G.srgbToLinear`), or the image washes out grey.
- **`Object3D.lookAt` points +z** at the target; cameras point -z. For a raymarch shader's camera basis
  use a `THREE.Camera` to call lookAt on, or the rays march away from the subject.
- **GLSL chunks injected with onBeforeCompile need a trailing newline**: `NOISE + '\n' + shader`, or the
  next `#define` lands mid-line and the program fails to compile.
- **Fog hides far hero objects.** A moon 175 units out vanished in fog far = 140. Give it `fog: false`,
  and emissive so it reads without lighting.
- **Bloom eats light colours.** Ivory type and pale materials bloom to white smears at the default
  threshold; keep bloom low (0.15-0.4) with threshold 0.85-0.95 and save it for emissive things.
- **Bright stacked transparency goes grey.** Four glass panes at 10 % opacity flattened the frame to grey;
  use ~3 % plus env reflections and give panes emissive frames for structure.
- **Cylinder UVs wrap the circumference (u) and run along the axis (v).** A counter drum lying on its
  side needs its digits laid out along u, each drawn rotated 90 deg; the digit facing the camera is at
  angle (digit + 0.5) / 10 of a turn. Reverse the strip so the next digit rolls up from below.
- **A dolly-zoom** keeps the subject's size with `fov = G.dollyFov(fov0, d0, d)`; it only reads if the
  background has strong perspective lines (a grid corridor) close enough not to be fogged out.
- Remove a deprecated three.js feature warning when you see one (e.g. PCFSoftShadowMap -> PCFShadowMap):
  console noise in renders hides the real errors.

## Look

The brand's palette still rules: lights tinted toward the palette, one accent colour on clearcoat
materials, ivory/oat/slate grounds. ACES tone mapping desaturates bright accents; darken the base colour
a little rather than raising exposure. 3-D for its own sake (a spinning logo on a gradient) is a template
look; every set should be a place or an idea the lyric or product line points at.
